# Еда и здоровье

Android-приложение (Kotlin, Compose, Room, Hilt) и сервер (Python, FastAPI, SQLite).
Требования — SPEC.md. Он главнее любых догадок: если ТЗ неполно или противоречит заданию, спроси.

## Правила работы
- Задание = одна подзадача из SPEC.md. Не делай больше, чем просили.
- Android-сборку локально не запускай: на сервере мало памяти, собирает GitHub Actions.
- Перед push: git pull --rebase (CI сам коммитит номер версии).
- Push в main только после законченной подзадачи. Каждый push — релиз.
- После push: gh run watch. Если сборка упала — gh run view --log-failed,
  исправь и пушь снова, пока не станет зелёной.
- Сообщение коммита — по-русски, оно попадает в описание релиза.
- Новая логика = новые unit-тесты (что покрывать — SPEC.md, раздел 10).
- Схема базы меняется только миграцией с тестом.
- Никогда: force push, удаление релизов и тегов, коммит ключей и паролей.
