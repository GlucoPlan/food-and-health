# Сервер «Еда и здоровье»: установка с нуля и переезд

Пошаговая инструкция на случай, когда сервер нужно поставить на новую машину. Все команды выполняются
в терминале сервера. Там, где нужен `sudo`, система один раз спросит ваш пароль.

Коротко:
- **новый сервер, данные не нужны** — шаги 1–6, затем 8–9;
- **переезд со старого сервера с данными** — шаг 7 на старом сервере, затем шаги 1–6 и 8–9 на новом.
  Ключ семьи и настройки Telegram переедут сами.

---

## 1. Что нужно заранее

| Что | Зачем |
|---|---|
| Сервер Linux: Ubuntu 24.04 (на ней проверено; нужен Python 3.12), от 1 ГБ памяти (лучше с 2 ГБ swap), от 5 ГБ диска | На нём работает сервер |
| Доступ по SSH пользователем с правом `sudo` | Для установки |
| Доменное имя, которое указывает на IP сервера (запись A). Подойдёт поддомен от хостера, например `51434.koara.live`, или бесплатный DuckDNS | Для HTTPS-сертификата |
| Открытые порты 80 и 443 в панели хостера (если там есть свой файрвол) | Let's Encrypt проверяет домен через порт 80, телефоны ходят на 443 |

Проверить, что домен смотрит на сервер: `getent hosts ВАШ-ДОМЕН` на самом сервере должен показать его IP.
Если домен только что заведён, записи расходятся по интернету от нескольких минут до часа.

## 2. Скачать проект

```
sudo apt-get update && sudo apt-get install -y git
cd ~
mkdir -p projects && cd projects
git clone https://github.com/GlucoPlan/food-and-health.git
cd food-and-health
```

Дальше все команды — из папки `~/projects/food-and-health`.

## 3. Установить сервер

```
sudo bash server/deploy/install.sh ВАШ-ДОМЕН
```

Скрипт сам:
- ставит Python, SQLite и Caddy (HTTPS);
- заводит системного пользователя `foodhealth` и папки (таблица ниже);
- ставит зависимости Python в отдельное окружение `/opt/foodhealth/venv`;
- **при первой установке создаёт ключ семьи** и печатает его в конце;
- создаёт `/etc/foodhealth/reports.json` — время завтрака, обеда и ужина для отчётов;
- запускает сервис и таймеры: резервная копия в 03:30, отчёты в Telegram в 6:00 по Москве;
- выпускает сертификат HTTPS и открывает порты 80 и 443 в ufw, если ufw включён;
- в конце проверяет, что `https://ВАШ-ДОМЕН/health` отвечает.

В конце будет строка «Ключ семьи: …». **Сохраните его** (например, в менеджер паролей): он вводится
в каждом телефоне. Посмотреть позже: `sudo cat /etc/foodhealth/env`.

При переезде ключ сейчас будет новый — это нормально, на шаге 7б его заменит старый.

| Что | Где |
|---|---|
| код и окружение Python | `/opt/foodhealth` |
| данные: база `fh.db`, фото кастрюль | `/var/lib/foodhealth` |
| ключ семьи, токен бота | `/etc/foodhealth/env` |
| кто чьи отчёты получает | `/etc/foodhealth/telegram.json` |
| время приёмов пищи для отчётов | `/etc/foodhealth/reports.json` |
| резервные копии (30 последних) | `/var/backups/foodhealth` |

## 4. Проверить, что сервер работает

```
systemctl status foodhealth --no-pager        # active (running)
curl -s -o /dev/null -w '%{http_code}\n' https://ВАШ-ДОМЕН/health    # 401 — так и должно быть: без ключа
systemctl list-timers 'foodhealth*' --no-pager                        # два таймера: backup и reports
```

## 5. Подключить телефоны

Новый сервер без данных (не переезд):
1. На каждом телефоне: Настройки → «Сервер» → адрес `https://ВАШ-ДОМЕН` и ключ семьи → «Проверить соединение».
2. Первый телефон отправит на сервер всё, что на нём есть. Лучше начать с телефона, где больше всего данных.
3. Остальные телефоны получат данные с сервера. При вопросе «объединить или заменить» выбирайте по ситуации:
   «объединить» сохранит записи с обеих сторон.

При переезде (шаг 7): если домен тот же, телефоны ничего не заметят. Если домен новый — на каждом
телефоне поменять только адрес, ключ прежний.

## 6. Настроить Telegram

1. В Telegram откройте @BotFather → `/newbot` → придумайте имя → получите токен.
   При переезде бот и токен остаются прежними — этот шаг пропустите.
2. Каждый, кто будет получать отчёты, пишет боту `/start`. Telegram хранит эти сообщения около суток,
   так что шаг 3 делайте в тот же день.
3. Запустите:
   ```
   sudo bash server/deploy/telegram-setup.sh
   ```
   Скрипт спросит токен (если его ещё нет), покажет, кто написал боту, и для каждого спросит,
   чьи отчёты присылать: номера профилей через запятую, `0` — ничего, Enter — оставить как было.
   Каждому уйдёт пробное сообщение.
4. Проверить отчёт сразу, не дожидаясь утра:
   ```
   sudo bash server/deploy/send-reports.sh                 # за вчера
   sudo bash server/deploy/send-reports.sh --week          # за прошлую неделю
   sudo bash server/deploy/send-reports.sh --date 2026-09-30 --force   # за день, даже если уже отправлен
   ```

Повторный запуск `telegram-setup.sh` меняет привязку или добавляет человека.
Сменить токен (например, если бот пересоздан): `sudo bash server/deploy/telegram-setup.sh --new-token`.

## 7. Переезд: забрать данные со старого сервера

### 7а. На старом сервере

```
cd ~/projects/food-and-health
sudo bash server/deploy/export.sh ~
```

Появится файл `~/foodhealth-export-ДАТА.tar.gz`. В нём база, фото, ключ семьи, токен бота,
настройки Telegram и отчётов. **Храните и передавайте его аккуратно** — с ним можно читать все данные семьи.

Скопируйте архив на новый сервер, например с домашнего компьютера:
```
scp старый-сервер:foodhealth-export-*.tar.gz .
scp foodhealth-export-*.tar.gz новый-сервер:
```

### 7б. На новом сервере (после шагов 1–4)

```
cd ~/projects/food-and-health
sudo bash server/deploy/restore.sh ~/foodhealth-export-ДАТА.tar.gz
```

Скрипт остановит сервис, восстановит данные, ключ семьи и настройки, запустит сервис и проверит его.
После этого `sudo cat /etc/foodhealth/env` покажет старый ключ — телефоны его уже знают.

Проверьте данные: `sudo bash server/deploy/diagnose.sh` — должны быть видны записи по профилям.

Старый сервер после проверки можно выключить. Если домен переехал вместе с сервером (запись A указывает
на новый IP), телефоны переключатся сами.

## 8. Настроить отчёты (по желанию)

`/etc/foodhealth/reports.json` — как делить приёмы пищи по времени в недельном отчёте дочери:
```
sudo nano /etc/foodhealth/reports.json
```
```json
{"meal_slots": [{"name": "Завтрак", "until": "11:00"}, {"name": "Обед", "until": "16:00"},
                {"name": "Ужин", "until": "21:00"}, {"name": "Поздний приём"}]}
```
Приём попадает в первый интервал, у которого время раньше `until`; у последнего `until` нет.
Правка действует сразу, перезапуск не нужен. Если в файле ошибка, берутся значения по умолчанию,
а причина пишется в журнал: `journalctl -u foodhealth -n 20`.

## 9. Обновление сервера

Когда в репозитории появилась новая версия:
```
cd ~/projects/food-and-health
git pull
sudo bash server/deploy/install.sh ВАШ-ДОМЕН
```
Ключ, данные и настройки не меняются. Перед крупным обновлением можно сделать копию:
`sudo bash server/deploy/backup-now.sh`.

---

## Резервные копии

- Каждый день в 03:30 по времени сервера (таймер `foodhealth-backup`), хранятся 30 последних,
  в `/var/backups/foodhealth/ГГГГ-ММ-ДД_ЧЧММСС`.
- Сделать сейчас: `sudo bash server/deploy/backup-now.sh`.
- Откатиться на копию: `sudo bash server/deploy/restore.sh /var/backups/foodhealth/2026-09-29_033000`
  (текущие данные перед этим тоже сохраняются копией).
- Копии лежат на том же сервере. От потери всего сервера спасает только архив `export.sh`,
  сохранённый в другом месте (или отправка копий в Telegram — подзадача 3-6).

## Если что-то не так

| Признак | Что сделать |
|---|---|
| `install.sh` пишет «HTTPS пока не отвечает» | Проверить, что домен указывает на этот сервер и порты 80/443 открыты у хостера; журнал Caddy: `journalctl -u caddy -n 50`. Можно запустить `install.sh` ещё раз |
| Телефон: «Неверный ключ семьи» | Сверить ключ с `sudo cat /etc/foodhealth/env` (строка `FH_FAMILY_KEY=`) |
| Телефон: «Нет связи с сервером» | `systemctl status foodhealth`; `journalctl -u foodhealth -n 50` |
| Отчёты в Telegram не пришли утром | `journalctl -u foodhealth-reports -n 30`; отправить вручную `send-reports.sh` |
| Отчёт пустой, хотя записи есть | `sudo bash server/deploy/diagnose.sh --date ГГГГ-ММ-ДД` — показывает, какие записи сервер видит по профилям и дням. Если записей нет — телефон их не отправил (на телефоне Настройки → «Синхронизация») |
| `telegram-setup.sh`: «Боту ещё никто не написал» | Каждый пишет боту `/start` и скрипт запускается снова в течение суток |
| Сервис не стартует после ручной правки `/etc/foodhealth/env` | Права: `sudo chown root:foodhealth /etc/foodhealth/env && sudo chmod 640 /etc/foodhealth/env` (`telegram-setup.sh` делает это сам) |

Все скрипты лежат в `server/deploy/`, подробности о протоколе и настройках — в `server/README.md`.
